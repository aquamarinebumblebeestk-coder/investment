# jpstock — 日本株 銘柄分析ツール (たたき台)

[J-Quants API](https://jpx-jquants.com/ja) (V2) を使って、銘柄コードを入力すると以下を表示します。

| 表示内容 | 取得元 |
| --- | --- |
| 株価・出来高 (直近10営業日、期間高安値、20日平均出来高) | `/equities/bars/daily` |
| 売上高・営業利益・純利益 | `/fins/summary` (決算短信) |
| EPS・PER・PBR・ROE・配当利回り・時価総額 | Free〜Standard: 株価と決算から計算 / Premium: `/equities/valuation` |
| 配当金 (年間配当の実績・会社予想、配当性向) | `/fins/summary`。Premium では `/fins/dividend` の権利落ち日等も表示 |
| 過去数年間の業績推移 (増収率・営業利益率・来期会社予想) | `/fins/summary` |
| **財務分析** (収益性・成長性・安全性・CF・期中進捗率と評価) | `/fins/summary` |
| **テクニカル分析** (移動平均・RSI・MACD・ボリンジャーバンド・出来高とシグナル) | `/equities/bars/daily` |

| **総合評価** (割安性・収益性・成長性・安全性・テクニカルの5段階評価と100点換算、強み/弱み) | 上記の計算結果 |
| **銘柄比較** (複数銘柄の主要指標と評価を1つの表に、総合評価順) | 上記の計算結果 |
| **Claude による分析レポート** (`--ai`、任意) | 上記の計算結果を Claude API に渡して文章化 |

財務分析・テクニカル分析・総合評価・比較は取得済みのデータから計算するため、J-Quants API の呼び出し回数は増えません。

## セットアップ (PC)

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
cp .env.example .env             # JQUANTS_API_KEY にダッシュボードで発行した API キーを設定
```

## 使い方

```bash
jpstock 7203                 # 1銘柄
jpstock "7203,6758,9984"     # 複数銘柄はカンマ区切り
jpstock                      # 引数なしなら対話入力
jpstock 7203 --plan light    # プランを一時的に指定 (既定は .env の JQUANTS_PLAN)
jpstock 7203 --days 180      # 株価の取得日数
jpstock 7203 --sections technical            # テクニカル分析だけ表示
jpstock "7203,6758" --sections basic,financial

# 取得結果を SQLite (data/jpstock.db) に保存し、後から API なしで分析する
jpstock "7203,6758,9984" --save
jpstock "7203,6758" --from-saved
jpstock 7203 --from-saved --as-of 2026-03-31   # その日までに得られたデータだけで分析

# Claude による分析レポート (別途 pip install -e ".[ai]" と ANTHROPIC_API_KEY が必要)
jpstock "7203,6758" --from-saved --ai --ai-out reports/analysis.md
```

`--sections` に指定できる値 (既定はすべて):

| 値 | 内容 |
| --- | --- |
| `basic` | 株価・出来高、指標、配当金、業績推移 |
| `financial` | 財務分析 |
| `technical` | テクニカル分析 |
| `summary` | 総合評価 |

複数銘柄を指定すると、最後に銘柄比較の表が出ます (`--no-compare` で非表示)。

## データ基盤 (SQLite)

取得データは SQLite (既定: `data/jpstock.db`) に保存します。

### 全銘柄の取得: `jpstock-data`

```bash
jpstock-data sync --dry-run     # 必要なリクエスト数と所要時間の見積もりだけ表示
jpstock-data sync               # プランの提供期間の全銘柄の株価・財務・銘柄一覧・取引カレンダーを取得
jpstock-data sync --codes 7203,6758       # 指定銘柄だけ (銘柄単位で取得)
jpstock-data sync --datasets bars --from 2026-06-01 --refresh   # 期間を指定して取り直す
jpstock-data status             # 件数・期間・取得済み営業日の割合・最終取得日時
jpstock-data check              # 欠損・異常値・鮮度のチェック
jpstock-data history            # 取得ログ
jpstock-data import-snapshots data/snapshots   # 旧形式 (JSON) の保存データを取り込む
```

- **日付単位で全銘柄を取得**するため、Free プラン (5回/分) でも全銘柄を扱えます。初回は過去2年分で約1,400リクエスト (約4〜5時間) かかります。2回目以降は未取得の日だけを取るので数分です。
- **中断しても再開できます。** 取得済みの日付を記録しているので、Ctrl+C やエラーで止まっても、再実行すれば続きから取得します。
- **調整後株価は読み出し時に計算します。** 生の四本値と調整係数を保存しておき、分割・併合があっても過去の値が不整合にならないようにしています。
- **更新履歴:** 再取得で値が変わった場合は旧値を残します (訂正開示も別レコードとして残ります)。
- **時点指定:** `--as-of` を付けると、その日までに開示・取引されたデータだけで分析します (第5段階のバックテスト用の土台)。

### 品質チェック (`jpstock-data check`) の内容

| 区分 | 内容 |
| --- | --- |
| 欠損 | 未取得の営業日、株価の欠けが多い銘柄、財務情報がない銘柄、終値のない行 |
| 異常値 | 高値 < 安値、終値・始値が高安の範囲外、0 以下の株価、負の出来高 |
| 急変 | 調整係数の変化なしで前日比 ±50% 超 (データ誤りの可能性) |
| 鮮度 | 取得可能な最新日から5営業日以上遅れている、最終取得から7日以上経過 |
| 取得ログ | 失敗・中断した取得の件数 |

要対応の問題があると終了コード 1 を返します。

**注意:** J-Quants の取得データは再配布が認められていません。`data/` は `.gitignore` 済みです。このリポジトリは公開設定のため、DB ファイルをコミットしないでください。

## 全銘柄スクリーニング (`jpstock-screen`)

`jpstock-data sync` で保存した全銘柄のデータから、条件に合う銘柄を抽出して並べ替えます。API は使いません。

```bash
jpstock-screen                                  # 総合評価の高い順に上位50銘柄
jpstock-screen --preset value                   # 割安株の条件セット
jpstock-screen "per<=12" "roe>=10%" "yield>=3%" --market プライム
jpstock-screen --preset growth --sort sales_cagr --limit 20
jpstock-screen --preset quality --csv data/out/quality.csv   # 結果を CSV に (Excel で開ける)
jpstock-screen --as-of 2026-03-31               # その日までのデータでスクリーニング
jpstock-screen --list-metrics                   # 使える指標とプリセットの一覧
```

- **条件の書き方:** `指標 演算子 値` (演算子は `< <= > >= = !=`)。複数指定は AND です。`%`・`万`・`億`・`兆` の単位が使え、全角でも入力できます。
- **既定の除外:** 業種「その他」(ETF・REIT 等) と、売買代金 (20日平均) が5,000万円未満の銘柄は除外します。`--include-others`、`--min-turnover 0` で解除できます。
- **データがない場合:** 条件に使った指標の値がない銘柄 (赤字で PER がない等) は、条件を満たさない扱いです。
- **所要時間:** 約4,000銘柄で20秒前後です (DB は2年分で約200MB)。

| プリセット | 条件 |
| --- | --- |
| `value` 割安株 | PER 0超15以下、PBR 1.2以下、配当利回り 2.5%以上 |
| `growth` 成長株 | 売上CAGR 10%以上、予想営業増益率 5%以上、営業利益率 5%以上 |
| `quality` 高収益・財務健全 | ROE 10%以上、営業利益率 10%以上、自己資本比率 40%以上、FCF プラス |
| `dividend` 高配当 | 配当利回り 3.5%以上、PER 0超、自己資本比率 30%以上 |
| `momentum` 上昇トレンド | テクニカルスコア +2以上、3か月騰落率 0%以上 |

## 総合評価の内容

各カテゴリを複数の指標で 1〜5 点に採点し、その平均をカテゴリ点とします。総合点はカテゴリ平均を 100 点満点に換算したものです。4 点以上のカテゴリを「強み」、2 点以下を「課題」として総評に出します。閾値は `src/jpstock/scoring.py` で調整できます。

| カテゴリ | 指標 (5点の目安) |
| --- | --- |
| 割安性 | PER 10倍以下、PBR 0.8倍以下、配当利回り 4%以上 (赤字の PER は採点しない) |
| 収益性 | 営業利益率 15%以上、ROE 15%以上 |
| 成長性 | 売上高の年平均成長率 10%以上、会社予想の営業増益率 10%以上 |
| 安全性 | 自己資本比率 60%以上 (金融業は対象外)、営業CF・FCF ともにプラス |
| テクニカル | 強気シグナル数 − 弱気シグナル数が +3 以上 |

## Claude による分析レポート (`--ai`)

計算結果 (指標・財務分析・テクニカル分析・総合評価・直近60日の株価) を JSON にして Claude API に渡し、銘柄ごとの分析と銘柄比較を Markdown で書いてもらいます。

```bash
pip install -e ".[ai]"
export ANTHROPIC_API_KEY=...          # Windows: set ANTHROPIC_API_KEY=...
jpstock "7203,6758" --ai --ai-out reports/analysis.md
```

- 既定モデルは `claude-opus-5-5`。`--ai-model` か環境変数 `JPSTOCK_AI_MODEL` で変更できます。
- Claude API の利用料金が別途かかります (J-Quants とは別契約)。
- 安全性フィルタで辞退された場合は、サーバー側で推奨モデルに自動で切り替えて再実行する設定にしています。
- AI の出力は渡したデータに基づく参考意見であり、投資助言ではありません。

## 財務分析の内容

- 決算期ごとの営業利益率・純利益率・ROE・ROA・自己資本比率・営業CF・フリーCF
- 売上高・営業利益・純利益・EPS の年平均成長率 (CAGR)
- 期中 (1Q〜3Q) の場合は通期会社予想に対する進捗率 (目安: 1Q 25% / 2Q 50% / 3Q 75%)
- 評価コメント (`[良好]` / `[注意]` / `[参考]`)。閾値は `src/jpstock/financial.py` 冒頭の定数で調整可能
  - 営業利益率 10% 以上で良好・5% 未満で注意、ROE 8% 以上で良好・5% 未満で注意
  - 自己資本比率 40% 以上で良好・20% 未満で注意 (銀行・保険など金融業は対象外)
  - 営業CF のマイナス、営業CF が純利益の半分未満、会社予想の減益、進捗の遅れ (目安 −10pt) を注意

## テクニカル分析の内容

- 移動平均 (5/25/75日) と並び順によるトレンド判定、ゴールデン/デッドクロス (直近5営業日)
- RSI(14) の買われすぎ (70以上) / 売られすぎ (30以下)
- MACD(12,26,9) とシグナルの位置・クロス
- ボリンジャーバンド (20日, ±2σ) の上抜け / 下抜け
- 出来高の急増 (20日平均の2倍以上)
- 強気シグナル数 − 弱気シグナル数で総合判定 (+2 以上: 強気、−2 以下: 弱気)

株価は分割・併合を調整した値を使います。パラメータは `src/jpstock/technical.py` 冒頭の定数で調整できます。
判定は機械的なものであり、売買を推奨するものではありません。

- 銘柄コードは4桁 (`130A` のような英字入り新コード可) または5桁 (`72030`)。全角数字・全角カンマも受け付けます。
- 終了コード: 0 正常 / 1 入力エラー / 2 取得できない環境のため中断 / 3 一部銘柄の取得に失敗

## 取得できない環境での動作

取得処理の前にプリフライトチェックを行い、以下のいずれかに当てはまると**警告を出して中断**します (終了コード 2)。

- クラウド/リモート実行環境 (スマホ等から Claude Code に実行を指示した場合など。`CLAUDE_CODE_REMOTE` で判定)
- API キー (`JQUANTS_API_KEY`) が未設定
- `api.jquants.com:443` に接続できない

ネットワーク許可を設定済みのクラウド環境など、接続できると分かっている場合に限り `JPSTOCK_ALLOW_REMOTE=1` でリモート判定を無効化できます。

## プランと拡張性

プランごとの差異は `src/jpstock/plans.py` に集約しています。有料プランに移行する場合は `.env` の `JQUANTS_PLAN` を変更するだけで、レート制限・取得期間・利用機能が切り替わります。

| プラン | リクエスト/分 | 提供期間 | 遅延 | 本ツールで追加される機能 |
| --- | --- | --- | --- | --- |
| Free | 5 | 過去2年 | 12週間 | — |
| Light | 60 | 過去5年 | なし | — |
| Standard | 120 | 過去10年 | なし | — |
| Premium | 500 | 過去20年 | なし | 配当詳細、J-Quants算出のバリュエーション指標 |

- 値は 2026-10 時点の公式ドキュメント調査に基づきます。最新情報は公式サイトで確認し、差異があれば `plans.py` を修正してください。
- `/equities/valuation` の対応プランは未確認のため Premium のみ有効にしています。403 が返った場合は自前計算にフォールバックします。
- Free プランは 5 リクエスト/分のため、1銘柄あたり約3リクエスト → 複数銘柄では待ち時間が発生します。
- Free プランは提供期間が2年のため、業績推移も直近2期程度になります。

## 開発

```bash
python -m pytest
```

構成:

```
src/jpstock/
  cli.py        コマンドライン入口
  codes.py      銘柄コード入力のパース
  config.py     .env / 環境変数の読み込み
  plans.py      J-Quants プラン定義 (レート制限・期間・機能)
  preflight.py  実行前チェック (取得できない環境なら中断)
  client.py     J-Quants API V2 クライアント
  analyzer.py   データ取得・整形・指標計算
  financial.py  財務分析
  technical.py  テクニカル分析
  scoring.py    総合評価
  datacli.py    データ基盤のコマンド (jpstock-data)
  screening.py  全銘柄スクリーニング
  screencli.py  スクリーニングのコマンド (jpstock-screen)
  store.py      SQLite への保存・読み出し
  sync.py       API から DB への同期 (日付単位・再開可能)
  quality.py    欠損・異常値・鮮度のチェック
  snapshot.py   1銘柄分のデータの入れ物 (旧 JSON 形式の読み書き)
  ai.py         Claude による分析レポート
  report.py     テキスト表示
```
